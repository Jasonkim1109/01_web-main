## 2. 완성 기준 검토

| 기준 | 결과 | 검토 내용 |
| --- | --- | --- |
| `header`, `main`, `footer` 사용 | 충족 | 두 페이지 모두 상단 내비게이션을 `header`, 본문을 `main`, 하단 저작권을 `footer`로 구성했습니다. |
| 페이지 간 navigation bar | 충족 | 두 페이지의 `header` 안에 프로필과 키워드 페이지를 오가는 링크를 넣었습니다. |
| 의미 없는 `<div>` 최소화 | 충족 | 두 페이지에서 불필요한 `<div>`를 사용하지 않고 `section`, `article`, `ul`, `li` 등 의미에 맞는 태그를 사용했습니다. |
| 웹 접근성 준수 | 충족 | `lang="ko"`, 명확한 제목 계층, `aria-label`, `aria-labelledby`, `aria-current`, 이미지 `alt`, 본문 건너뛰기 링크를 적용했습니다. |
| 반응형 화면 | 충족 | 좁은 화면에서 프로젝트 카드와 기술 목록이 자연스럽게 줄바꿈되도록 구성했습니다. |
| 포트폴리오 내용 | 충족 | 프로필, 기술 스택, 자기소개 키워드, 작업물 링크를 한 사이트 안에서 확인할 수 있습니다. |

## 3. 페이지별 검토

### 프로필 페이지

- 자기소개를 첫 화면의 `h1`으로 배치해 페이지 목적이 분명합니다.
- 기술과 도구를 각각 `section`으로 나누고 배지를 `ul`과 `li` 목록으로 구성했습니다.
- `Selected Work` 영역에서 기존 학습 파일 세 개로 이동할 수 있습니다.
- 프로젝트 카드에 마우스와 키보드 포커스 상태를 적용했습니다.

### 키워드 페이지

- 세 가지 자기소개 내용을 각각 `article` 박스로 구분했습니다.
- 프로필 페이지와 동일한 내비게이션, 색상 체계, footer를 사용합니다.
- 긴 질문도 모바일 화면에서 한 열로 배치되어 읽기 쉽습니다.

## 4. 검증 결과

- 두 HTML 파일의 편집기 진단: 오류 없음
- 브라우저 접근성 트리 확인: `banner`, `navigation`, `main`, `region`, `article`, `contentinfo`가 정상 인식됨
- 프로젝트 링크 대상 파일: 모두 존재함
- 키보드 접근성: 본문 건너뛰기 링크와 링크 포커스 스타일 확인

## 5. 남은 개선 사항

- 프로필 배지와 배너가 외부 서비스 이미지이므로 인터넷 연결이 없으면 표시되지 않을 수 있습니다. 필요하다면 이미지를 저장해 로컬 자산으로 관리할 수 있습니다.
- 현재 작업물은 학습 예제 중심입니다. 실제 포트폴리오 제출용으로 발전시키려면 각 프로젝트에 사용 기술, 담당 역할, 해결한 문제, 실행 화면을 추가하는 것이 좋습니다.
- 연락처나 GitHub 링크를 추가하면 방문자가 다음 행동을 하기 쉬워집니다.

## 6. 종합 의견

현재 결과물은 요청한 시맨틱 HTML, 페이지 내비게이션, 접근성, 반응형 디자인 기준을 충족합니다. 프로필과 키워드 페이지가 하나의 포트폴리오 사이트처럼 연결되어 있으며, 기존 학습 파일을 작업물로 재활용한 구성도 확인 가능합니다.
